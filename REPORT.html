0. 摘要

做了什么。 在固定 Br=4096、G=8、每 run 32,768 responses 的同一预算下，只操纵"每批 rollout 被重复用于几次优化更新"这一个变量：µ ∈ {1, 8, 16}（对应每步批大小 b = 4096 / 512 / 256），三个随机种子。三臂共享同一初始权重、同一冻结题池、同一 prompt 序列。

主结论（预注册 C3）没有被检验，而不是被证伪。 预注册把 N_τ 操作化为"drift clock 达到初始值 2 倍的 rollout 序号"，据此对照论文 Eq.(5) 的 6.1× 预测（C3 文本把这个比值的方向写反了，见 §1.1 脚注；因两端均删失，方向不影响判定）。实测 9/9 run 的 d/d0 全程落在 [0.926, 1.116]，阈值一次也没有触发，分子分母双双右删失，比值不存在。这不是"预测错了"，是"这个判据在本配置下不可触发"（§5.2、§7.3）。

测到了什么。 四条有实质内容的观测：一条与预注册同向但只部分成立、一条与预注册相反、一条通过、一条在预注册之外、后来被归因实验接住并升格为主结论。

1. 研究问题与预注册

1.1 被审计的对象

论文的 progress clock（Eq.5）给出达到进展阈值 τ 所需样本数

N_τ = N_min · (1 + Br / B*),        B* ∝ µ        (Eq.6)

固定 Br 时增大 µ 会增大 B*，于是 N_τ 下降——µ 越大，同样进展越省样本。按作者在 Remark 7 给出的 B*(µ=8) ≈ 4k 线性外推，µ 从 1 提到 16 应使所需样本相差约 6.1×（9.2 / 1.5），这是本次要对照的预测值。

预注册有一处方向笔误，本报告发现但不修改它：claims.yaml C3 把预测写成 N_τ(µ=16)/N_τ(µ=1) = 6.1×，而 6.1× 实际对应的是 N_τ(µ=1)/N_τ(µ=16)（9.2 / 1.5 = 6.13）。也就是说 C3 的比值方向与它引用的 6.1× 相反。这不影响本报告的判定——两端都右删失，任何方向的比值都不存在——但按预注册纪律，修订要加 revision 行并留痕，因此保持原样并记录在此（§8.4 待拍板）。

这条预测成立的前提是 Eq.(5) 的推导采用了假设 A2：一个 rollout 内的 µ 个 mini-batch 被当作彼此独立的新数据，陈旧性代价被"另外建模"而不进入 progress 项。本项目的增量就是把这一项单独测出来：如果陈旧性有代价，那么 µ 增大在样本口径上的收益会被打折，实测比值应低于 6.1×。

3. 方法

3.1 为什么自写训练循环

TRL 1.16 的 GRPOConfig.num_iterations 能表达 µ，但不暴露 per-µ-step 的 KL(π_θ‖π_rollout)、被 clip token 的梯度份额、以及 micro-batch 间的梯度散度 σ。这三者正是 A2 代价的直接观测面，因此改为自写循环：src/train.py 793 行（主循环）+ src/grpo.py 172 行（目标函数与 drift clock），src/ 合计 2,792 行。正确性用独立标量实现 + 有限差分自证。

测试共 37 项（6 个文件：test_grpo.py 6（标量参考 + 有限差分）、test_prompt_log.py 12、test_pipeline.py 11、test_rollout_archive.py 5、test_adapter_snapshot.py 3）。最近一次实跑 2026-10-27：Windows conda py3.11 + torch 2.3.0+cu121，37/37 通过，9.64 s（更早一次是 WSL py3.11 + torch 2.9.1，25/25 / 2.16 s——当时只有 4 个文件、25 项）。

3.6 统计口径

  • 配对，不合并。 三臂共享 seed，故报逐 seed 配对差，不报"三臂均值 ± 合并 CI"。
  • 不做跨 seed 的置信区间。 make_table.py 在 seed < 3 时明确拒绝打印 CI；本次 n=3，只报三个点与其极差（臂内 pass 极差 0.0071 / 0.0137 / 0.0112）。
  • 不插补删失。 未达到阈值即记 censored，不外推时间常数，不做 Tobit / Kaplan-Meier。

5.3 C4：初始 drift clock 随 µ 上升，方向与预注册相反

预注册假设："b = Br/µ 变小 → 梯度噪声相对变大 → d 下降"。实测：

arm d0 ‖ḡ‖@r0 σ@r0 σ/‖ḡ‖
µ1（b=4096） 0.0689 0.00454 0.06596 14.53
µ8（b=512） 0.1331 0.00885 0.06652 7.52
µ16（b=256） 0.1812 0.01221 0.06733 5.51

拆解：‖ḡ‖ 涨 2.69×，σ 只涨 1.02×，于是比值升 2.63×。σ 几乎不变的原因在口径里：σ 的估计窗口是固定的 8 条 response（micro_group_responses: 8），不随 b 缩放；而 ‖ḡ‖ 是实际批上的梯度范数，批越小噪声贡献越大，范数反而上升。

方向判定：预注册要求 d 随 µ 下降，实测 3/3 seed 同向上升，符号相反，d0 的配对比值 1.85 / 1.93 / 2.01（µ8）与 2.52 / 2.65 / 2.73（µ16），无一例外。

解释边界：预注册的机制猜测（噪声主导）被证伪，但这不等于"论文错了"。实测的"d0 随 µ 升"与同预算 pass 排序（§6）方向一致，都指向"µ 大时单位数据更有效"；而论文 Eq.(6) 的 B* ∝ µ 恰好预测 µ 大更省样本。两者方向是否一致，取决于 d 到 N_τ 的映射，本实验没有独立测 progress，故不作断言（§7.3）。

升格后的表述是：同样把预算翻一倍，拿去多切几次更新的收益（+9.31 pp）是拿去每轮多采数据的收益（+3.56 pp）的约 2.6 倍，且后者单独测不出来。 设计、混淆声明与"不能说什么"见 ATTRIBUTION.md §3.2。

原来只标探索性的三个理由，逐条更新：

  • (a) 登记时点不能改。 它仍然不在预注册里。升格改变的是结论地位，不改变"事后登记"这个事实——任何引用都必须带 post-hoc 标签。
  • (b) 它测的不是"样本效率"，而是"同数据预算下多做更新步"的效应。 µ 只改变"同一批数据被切成几次更新"（8 / 64 / 128 步），每 token 仍然只被 update 一次，所以三臂总 response 数相同、总 FLOPs 也几乎相同（1.84 / 1.78 / 1.76e17，即 1.000 / 0.968 / 0.959×，这点差来自生成长度而非更新量）。

    原稿在此处写的"所以它测的是优化步数而非样本效率"，后半句是错的，本次删去。步数多 µ 倍的同时每步样本少 µ 倍，总样本量与总算力都不变，所以真自变量既不是"样本效率"也不是"步数"，而是每步数据离当前策略有多远（off-policy 程度）。这个更正由 b×µ 2×2 逼出来：若真自变量是步数，则固定 b 只改 µ 也应有同等效应，而实测 µ 主效应是 b 的 2.6 倍——方向对，但量级说明两者不是同一个东西。

  • (c) 它与 C3 的 N_τ 口径不是同一个量，不能互相替代；升格不改变这一点。

换句话说："µ 大末段 pass 高"仍然不能读成"µ 提高样本效率"——样本数一样、算力一样。这是审稿最容易被追问的一句，也是简历上最容易说穿的一句。

值得注意的是：这条结果与 C4 的实测方向自洽（都是"µ 大更好"），而与 C4 的预注册机制猜测矛盾。这个内部一致性是本报告最值得记录的一点，也是最需要外部复核的一点。

但机制解释只完成了一半。 C9 证明 σ 的 µ 依赖既不是切分造成的（极差 0.26%），也不是策略陈旧造成的（1.020 vs 阈值 1.20），按它自己的判定规则必须"列为未解释的混淆项"。所以"为什么 µ 大更好"在本项目结束时没有底层解释，只有归因层的答案（是 µ 不是 b）。这条否定结论与升格是捆绑条件：只报升格、把否定结论压在附录里，等于用升格换叙事（§8.4）。

7.3 构念效度（本报告最关键的一节）

  1. N_τ 的代理不成立。 预注册用"d/d0 达到 2"代理 progress 阈值。实测 d 是平稳量（0.93–1.12），而 pass 从 0.22 涨到 0.48——progress 在动，代理不动。这说明该代理在本任务上无效，C3 的"未检验"首先是代理失效，其次才是视界不足。若要重做，应直接测 held-out 的 progress 曲线（每题固定评估集），而不是用 drift clock 的比值当阈值。
  2. d 的绝对标度不可比。 κ 是量纲约定，取 1.0；所有比较只用比值。跨模型/跨任务的 d 数值没有意义。
  3. KL 是采样估计。 每 run 11–29 行负值，早期步噪声大于信号。因此"C2 单调"这条判据在现有测量精度下原则上不可判定，不是策略不走。
  4. clip 两种份额不可互换。 本实验测 logprob 空间质量份额，论文报参数空间范数份额。二者在非均匀 A 下不相等。

8. 结论

8.1 能支持的陈述

  1. 测量器可用：72/72 个 mu_step=0 行显示新旧策略同源（|ratio−1| ≤ 1.04e-8、clip=0、KL=0），在真实权重与真实 µ 上。
  2. A2 忽略的 KL 项非零且随 µ 增长：末步 3.21e-4（µ8）与 4.49e-4（µ16）nats/token，µ16/µ8 = 1.40×，对 µ 次线性。
  3. 该 KL 项在 rollout 内不单调（上升比例 50–66%），测量精度不足以判定逐 step 行为。
  4. 初始 drift clock 随 µ 上升 2.63×（3/3 seed），与预注册的机制猜测相反。
  5. 响应长度无系统上涨（−4.3%）；成本两口径都在阈值内（¥32.40 内部 / ¥47.3 容器）。
  6. N_τ 的比值在 8 rollout 视界内不可识别：9/9 run 右删失，判据从未触发。
  7. （第二条主结论，事后归因后升格）同预算下 µ 是 pass 的主因、b 不是：µ 主效应 +9.31 pp [+5.77, +12.85]，b 主效应 +3.56 pp [−1.04, +8.17]（含 0），交互 +2.93 pp 含 0 故可加。这一条必须与"机制未解释"（C9）并列读，单引前半句即为误导。

8.2 不能支持的陈述

  • 不能声称"论文 Eq.(5) 的 6.1× 被证实/被证伪"——没有测到。
  • 不能声称"µ 越大越好"是普适结论——即使已升格，它仍是单模型（1.7B）、单任务（counting）、LoRA 3.89%、同预算内的结论。
  • 不能声称"µ 提升样本效率"——三臂总 responses 相同（各 32,768 × 3 seed），FLOPs 1.000 / 0.968 / 0.959×，差来自生成长度；真自变量是 off-policy 程度。这一句最容易被一句追问打穿。
  • 不能声称"我们知道 µ 为什么更好"——C9 给出的是否定结论：σ 的 µ 依赖既非切分（极差 0.26%）也非陈旧（1.020 vs 1.20），未解释。归因只到"是 µ 不是 b"这一层。
  • 不能声称"clip 的梯度份额低于 token 份额"反驳了论文——口径不同。
  • 不能把 d0 的臂间差异全部归因于陈旧性——主表三臂里 µ 与 b 共线，性能侧的解耦不迁移到 d0 侧（§7.1）。
