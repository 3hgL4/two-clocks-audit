# 2026-10-26 现有数据复核：这份数据到底能支撑什么

> 范围：`runs/` 里已归档的 9 个 run（3 个 µ × 3 seeds）、600 行 `metrics.jsonl`、72 个 rollout × 3 臂。
> 性质：**读数据**，不是结论报告；判据是否成立归用户拍板。所有数字都附口径与复算方式。
> 标签：〔实测〕= 由本地归档现场算出；〔推算〕= 由实测外推；〔待查〕= 有观察、机制未明。

## 0. 一句话

**这份数据比它自己的报告写得更能说话。** 现有的 8-rollout 数据已经足以把论文 Eq.(5) 的 `N_τ` 比夹在 **µ1/µ8 ≈ [2.8, 6.8]、µ1/µ16 ≈ [3.5, 8.5]**（点估计 **5.0 / 6.1**），而这 **不需要再烧一张卡**。真正缺的不是"更长的曲线"，而是两样东西：**per-prompt 粒度的日志**，和一个**口径修正**（`zero_var_group_frac` 现在量的不是它名字说的东西）。

## 1. 数据面：有什么，没有什么

**有**（每行 = 一个 µ-step，共 600 行）〔实测〕：

| 维度 | 内容 |
|---|---|
| 设计 | 3 臂（µ=1/8/16）× 3 seed（0/1/2），每臂 8 rollouts |
| 每 rollout | 4096 responses = 512 prompts × 8 generations，**三臂相同** |
| 指标 | pass_rate、reward_mean、resp_len、σ、d、KL、clip 份额、‖ḡ‖、墙钟、¥、FLOPs |
| 采样留痕 | `rollouts/rNNN.npz` 存了逐 token 的 prompt/completion id + sha256 |
| 起点控制 | µ1 与 µ8 的 r0 数据 **sha256 逐位相同**〔实测〕；µ16 略有差异（见 §12） |

**没有**（这才是限制）：

- `samples.jsonl` 只存每个 rollout 的**前 8 条 response**，而布局是 `[p0_g0..p0_g7, p1_g0...]`，所以它存的是**第 0 个 prompt 的整个 group**——每个 rollout 只有 1 个 prompt 的明细，全实验共 72 个 group。
- 因此：**group 级 pass、组内相关（ICC）、难度分层、"首见 vs 重见"全部算不出来**。所有分析只能停在聚合量上。

## 3. 曲线形状：µ1 在加速，µ8/µ16 在减速〔实测〕

把斜率分段算（r0–r4 是"lr 还高"的阶段，r4–r7 是"lr 掉 12 倍"的阶段）：

| arm | slope r0–r4 | slope r4–r7 | 比值 | 读法 |
|---|---|---|---|---|
| µ1 | 0.00640 | 0.00790 | **×1.23** | 加速 |
| µ8 | 0.04370 | 0.02205 | ×0.50 | 减半 |
| µ16 | 0.05444 | 0.02799 | ×0.51 | 减半 |

**这条推翻了我上一轮的一个读法。** 我之前担心"µ1 末端放缓是退火到冻结的假象"——数据说不是：µ1 在 lr 掉到 2.5e-6 时反而**加速**，µ8/µ16 才是减速的那两个。

结论应当是：**µ1 在 8 个 rollout 内远未饱和，C3 的"不可识别"是视界截断，不是"µ1 学不动"。** 而 µ8/µ16 的减速更像在逼近题池（深度 1–7、512 token 上限）允许的天花板。

## 4. 判据可算性：不需要续跑也能得到 `N_τ` 比〔实测 + 假设〕

**推导**：三臂起点相同（r0 = 0.2217 / 0.2217 / 0.2216，µ1 与 µ8 甚至是逐位相同的采样），若 pass 在窗口内对 responses 近似线性，则达到同一阈值 τ 所需样本数

```
N_τ(µ) = (τ − p0) / slope(µ)   ⇒   N_τ(µ)/N_τ(µ') = slope(µ')/slope(µ)
```

**逐种子斜率比 → `N_τ` 比**〔实测〕：

| 比较 | 三个种子 | 均值 | 种子极差 |
|---|---|---|---|
| N_τ(µ1)/N_τ(µ8) | 4.66 / 4.80 / 5.47 | **4.98** | 0.81 |
| N_τ(µ1)/N_τ(µ16) | 5.99 / 5.62 / 6.80 | **6.14** | 1.18 |

**窗口敏感性**（同一个数在不同窗口上取值，这是系统误差的主来源）〔实测〕：

| 窗口 | µ1/µ8 | µ1/µ16 |
|---|---|---|
| r0–r4 | 6.82 | 8.50 |
| r0–r7（全窗口） | 4.96 | **6.10** |
| r1–r7 | 4.77 | 5.86 |
| r2–r7 | 4.10 | 5.07 |
| r4–r7 | 2.79 | 3.54 |

**统计误差**：单种子 pass 的 binomial SE 在 4,096 responses 上为 0.0065–0.0078；8 点线性拟合的斜率 SE ≈ SE/√42 → µ1 斜率（0.0075）相对误差约 **8–10%**，µ16（0.046）约 2%。所以 `N_τ` 比的统计误差约 **±8%**（6.14 → 6.14 ± 0.5），而窗口系统误差是 **−43% / +38%**——后者大一个量级，必须一起报。

**怎么读这个数**：点估计 6.10 与论文 Eq.(5) 的 6.1× 数值相同，但**不能叫复现**：
1. 判据不同（斜率比 vs 原文的 `N_τ`，progress 的定义也不同）；
2. 任务、模型、题池都与原文不同；
3. 原文 6.1× 在本项目 `claims.yaml` 里曾把方向写反（`REPORT.md` §1.1 脚注）；
4. 区间 [3.5, 8.5] 覆盖它，点估计落在区间中段偏下。

诚实的措辞是：**"同向、同量级，且点估计与原文数值吻合，但窗口不确定度 ±40%，不构成复现。"**

**这个方法比"续跑到穿越"硬在哪**：同一窗口内三臂共用同一 LR 调度，调度效应在比值的分子分母里同时出现，**自动抵消**。而"续跑"会在 r8 处引入 13.6× 的 lr 跳变（`--num-rollouts 19` 会重算余弦周期），那才是真正的混杂。

## 5. 噪声底：穿越点只能定到 ±1 个 rollout〔实测〕

| p | binomial SE（4,096 responses） |
|---|---|
| 0.222 | 0.0065 |
| 0.269 | 0.0069 |
| 0.46 | 0.0078 |
| 0.52 | 0.0078 |

µ1 的斜率是 0.0075/rollout → **一个 rollout 的位移 = 1 个 SE**。所以"穿越 0.30 的 rollout 号"精度就是 ±1（±4,096 responses，约 ±7%）。这在判据上可以接受，但意味着**不要把穿越点报成两位小数**。

## 6. "同预算"到底同不同：三重核对〔实测〕

| 口径 | µ1 | µ8 | µ16 | 结论 |
|---|---|---|---|---|
| responses | 32,768 | 32,768 | 32,768 | 相同（设计使然） |
| 题集 | 同一 seed 下逐 rollout **完全相同** | 同 | 同 | 相同（`prompt_batch` 是纯函数） |
| completion tokens | 9,774,736 | 9,445,895 | 9,352,247 | µ8 −3.4%、µ16 −4.3% |
| 墙钟/run | 1.76 h | 1.73 h | 1.73 h | 基本相同 |
| 墙钟里 update 占比 | 62.9% | 62.5% | 62.6% | 一致 |
| 记账 ¥/run | 3.66 | 3.47 | 3.42 | 一致（差 7%） |

**所以 µ16 用少了 4.3% 的 token、同样的墙钟，换来 2.3× 的 pass。** "同预算"这条站得住，而且对 µ>1 略偏保守。

**成本归一化**〔实测〕：每 +1pp pass 花 ¥0.776（µ1）/ ¥0.146（µ8）/ ¥0.116（µ16）——µ16 比 µ1 便宜 6.7×。

## 7. `d` 的恒定是"抵消"，不是"稳定"〔实测，建议回改报告〕

`d = κ‖ḡ‖/σ`，两个分量都随训练上升，且上升倍数几乎相同：

| arm | ‖ḡ‖ r0→r7 | σ r0→r7 | d r0→r7 |
|---|---|---|---|
| µ1 | ×1.044 | ×1.005 | ×1.039 |
| µ8 | ×1.216 | ×1.247 | ×0.975 |
| µ16 | **×1.404** | **×1.424** | ×0.988 |

µ16 的分子与分母都涨了 40%，d 当然平。所以 C5 的"d 基本不变"是**弱通过**：它说明的是比值稳定，不说明训练动力学稳定。报告目前的写法（C5 作为"标尺可用"的证据）应当补上这个限定。

另：σ 与 `zero_var_group_frac` 的臂内相关系数 µ8 +0.927、µ16 +0.898（µ1 +0.174）→ σ 有一部分在追踪"难度饱和"，不纯是梯度噪声。

## 8. `zero_var_group_frac` 现在量的不是它名字说的东西〔实测 + 推导，需回改报告 §5.10〕

reward 是**连续**的（错答案 −0.1 / 0.05 / 0.1，对答案 1.0 / 1.05 / 1.1），所以"8 个样本 reward 完全相同"要求**连格式奖励也一致**。用 iid 反事实做对照：

| arm | pass@r7 | iid 下全错概率 | iid 下全对概率 | 观测 zero_var |
|---|---|---|---|---|
| µ1 | 0.269 | 8.16% | 0.003% | **0.46%** |
| µ8 | 0.459 | 0.73% | 0.198% | 7.75% |
| µ16 | 0.517 | 0.30% | 0.509% | **9.31%** |

- µ1：iid 下应有 8.2% 的组全错，观测 0.46%——说明绝大多数全错组被**格式抖动**拆开了（有的样本 `Answer:` 有的没有）。所以 µ1 的 zero_var≈0 **不是"没有 dead prompt"**。
- µ16：iid 下全对只有 0.51%，观测 zero_var 9.31%——至少 9% 的组是"8 个全对且格式一致"，是 iid 的 **18 倍**。组内正确性**强正相关**（题要么会要么不会），有效样本量远小于 8。

**结论**：这个指标在不同臂上量的不是同一件事（µ1 量的是格式抖动，µ16 量的是全对饱和），**不能用它当"饱和"的证据**。报告 §5.10 现在的两读法（"饱和"vs"漂移"）应改成"这个指标本身口径不干净，需按 correctness 布尔重算"。

## 9. 题池复用：实测，不是估算〔实测〕

用 `rollouts/rNNN.npz` 里的 prompt token id 做哈希（同一 pool item → 同一 id 序列 → 同一哈希，不需要 tokenizer）：

| 指标 | 值 |
|---|---|
| 8 rollouts 覆盖 distinct prompts | 1,797–1,829 / 2,000（**89.9%–91.5%**） |
| 复用倍数 | **2.24–2.28×** |
| 相邻 rollout 重叠 | 25.0%–25.9%（理论 512/2000 = 25.6%） |
| r0 ∩ r7 重叠 | 26.2%–26.8% |
| 投影到 19 rollouts | distinct ≈ 1,985（99.2%），复用 **4.90×** |

**臂间不受影响**（同一 seed 下三臂题集完全相同），但**续跑会让后段几乎全是复习**：19 个 rollout 时池子已经见底，之后每涨一点 pass 都要跟"复习效应"纠缠。这是"续跑到 19"必须一起报的威胁。

复现：`python analysis/prompt_overlap.py`（需 numpy）。

## 10. 一个未解释的观察〔待查，影响 ≤0.5pp〕

µ16 三个 run 的 **r0 采样哈希与 µ1/µ8 不同**，而 µ1 与 µ8 之间逐位相同〔实测〕：

| seed | µ1 r0 sha | µ8 r0 sha | µ16 r0 sha | µ16 pass − µ1 pass |
|---|---|---|---|---|
| 0 | 82bbd063c0dfcff6 | 82bbd063c0dfcff6 | a54b97dc27899823 | +0.47pp |
| 1 | 1b6819d3051d406d | 1b6819d3051d406d | 775d0e11b94639bf | −0.22pp |
| 2 | deb3c6df8f7511f7 | deb3c6df8f7511f7 | db4e2dbfb591c9d4 | −0.27pp |

同主机、同 commit（f04df9ff）、同 vLLM 0.32.0；`generate` 的 batch_size 取 `responses_per_rollout`（`src/rollout.py:240`），三臂都是 4096，`train.py` 也不传该参数。**所以差异不该出现，机制未查明。** 影响面：≤0.47pp，小于 0.65pp 的 binomial SE，不改变任何比较；但它让"µ16 与 µ1 起点完全相同"这个控制只剩"统计上相同"，而 µ1 vs µ8 仍是逐位相同。

补一条刚核过的：**题集三臂逐位相同**（含顺序，3 个 seed × r0 全部一致）〔实测〕——所以差异只在 **completion**，不在 prompt。结论不变：µ1 vs µ8 连 completion 都逐位相同，µ16 的 prompt 相同但 completion 不同。

## 11. 改进方向（按 价值/成本 排序）

| # | 方向 | 花费 | 产出 | 风险 |
|---|---|---|---|---|
| **R1** | **把 `N_τ` 比改成主判据**：同窗口斜率比 + 窗口区间 + 统计误差，写成新预注册 C8 | **¥0** | C3 从"不可识别"变成 `5.0 [2.8,6.8]` / `6.1 [3.5,8.5]` | 线性假设（µ8/µ16 已可见减速 → 真值偏区间低端）；必须写成"代理判据" |
| **R2** | **per-prompt 日志**（每 rollout 落 `prompt_id + 8×correct + 8×reward`，约 3 行代码）；同时把 zero_var 改成按 correctness 算 | **¥0** | 解锁 group-level pass、ICC、难度分层、首见/重见；修掉 §8 的口径错 | 只对**未来**实验有效，已归档的 9 run 补不回来 |
| **R3** | **warm-restart 探针**：只把 µ1_s0 续 1 个 rollout，看 r8 是持平/涨/崩 | **≈¥1**（13 min + 重建） | 买"要不要投 R4"的答案 | 只有 1 个点，噪声 ±0.7pp |
| **R4** | 续跑到 19（3 seeds） | **≈¥16**（7.9 h） | µ1 的 0.30 穿越点；检验 R1 的线性假设 | 边际价值已从"得结论"降级为"验假设"；后段 4.9× 复习效应 |
| **R5** | 报告回改四处：§5.10 zero_var、C5 的"抵消"限定、pool reuse 实测数、µ1 加速/µ8-16 减速的斜率分解 | ¥0 | 报告自洽 | 无 |
| **R6** | 扩池重跑（把复习效应压住） | ≫¥100 | 干净 | 不推荐 |
| **R7** | 加一个 µ4 测曲率 | ≈¥4（1 seed）/ ¥11（3 seeds） | 直接检验线性假设 | 只有 1 个中间点，收益低于 R1 |

**我的排序（供否掉）**：R1 + R5 今天做完（¥0），R2 顺手改（¥0，为后续所有实验铺路），R3 花 ¥1 买信息，**R4 暂缓**——因为 R1 已经能给出一个可报告的数，而 R1 的主要弱点（线性假设）恰恰只有 R4 能验，所以 R4 的位置从"补实验"变成"R1 的可信度保险"，值不值 ¥16 取决于你要不要把它写进简历/论文的主结论。

## 13. 三态清单

**已核实**（本地复算，命令在上文）：三臂逐 rollout pass / reward / 长度 / σ / ‖ḡ‖ / d；分段斜率与加速/减速方向；斜率比与窗口敏感性；逐种子 `N_τ` 比；binomial SE；token 与墙钟三重核对；¥/1pp；σ–zero_var 相关；题池 distinct/reuse/重叠（npz 哈希）；µ1 与 µ8 的 r0 数据 sha 相同、µ16 不同。
