## 1. R1：斜率比判据（新增 `analysis/slope_ratio.py` + `analysis/out/slope_ratio.json` + `claims.yaml` C8）

### 1.1 判据的形状

```
N_τ(µ) = (τ − p0) / slope(µ)   ⇒   N_τ(µ)/N_τ(µ') = slope(µ')/slope(µ)
```

三条性质决定了它值得单独立一条：

1. **τ 消掉了。** 比值与阈值无关，所以决策卡里那个"0.30 还是 0.35，选错就白跑"的参数不存在了。代价是引入线性假设。
2. **LR 调度自动抵消。** 三臂在 r0–r7 内共用同一条余弦退火，调度对斜率的影响在分子分母里同倍出现。而续跑（R4）会在 r8 处把 lr 从 2.48e-6 跳到 3.36e-5（13.6×），那才是把调度效应带进测量的做法。
3. **可以在数据内部自检**（见 1.3）。

### 1.2 点估计与区间〔实测〕

主口径：逐种子算比值再平均（三臂按 seed 配对），窗口 r0–r7。

| 比值 | 均值 | 逐种子 | 种子极差 |
|---|---|---|---|
| `N_τ(µ1)/N_τ(µ8)` | **4.98** | 4.66 / 4.80 / 5.47 | 0.81 |
| `N_τ(µ1)/N_τ(µ16)` | **6.14** | 5.99 / 5.62 / 6.80 | 1.18 |
| `N_τ(µ8)/N_τ(µ16)` | **1.23** | 1.28 / 1.17 / 1.24 | 0.11 |

窗口敏感性（系统误差的主来源）：

| 窗口 | µ1/µ8 | µ1/µ16 | µ8/µ16 |
|---|---|---|---|
| r0–r4 | 7.31 | 9.17 | 1.25 |
| **r0–r7（主）** | **4.98** | **6.14** | **1.23** |
| r1–r7 | 4.77 | 5.87 | 1.23 |
| r2–r7 | 4.11 | 5.09 | 1.24 |
| r4–r7 | 2.82 | 3.59 | 1.27 |

区间：`N_τ(µ1)/N_τ(µ8) ∈ [2.82, 7.31]`（−43% / +47%），`N_τ(µ1)/N_τ(µ16) ∈ [3.59, 9.17]`（−41% / +49%）。

统计不确定度三档（打在同一份 `slope_ratio.json` 里，因为只报一档会误导）：

| 比值 | iid 二项 95% CI | 设计效应 3 | 残差自助 |
|---|---|---|---|
| µ1/µ8 | 4.30–6.10 | 3.93–7.83 | 4.26–6.41 |
| µ1/µ16 | 5.31–7.51 | 4.85–9.65 | 5.26–7.88 |
| µ8/µ16 | 1.18–1.29 | 1.14–1.33 | 1.11–1.39 |

**统计误差（约 ±20%）比窗口系统误差（−41%/+49%）小一个量级**，所以报告必须以窗口区间为准，统计 CI 只说明"不是噪声"。

另：pooled 口径（先拟合种子均值曲线）在主窗口上给出 4.96 / 6.10 / 1.23，与逐种子口径几乎相同；但在 r0–r4 上给出 6.82 / 8.50，明显低于逐种子的 7.31 / 9.17。短窗口下**只报 pooled 会低估不确定度**，所以脚本两个都写进 JSON，正文只引逐种子的。

### 1.3 方法自检：µ8 vs µ16 这一对不需要线性假设〔实测〕

µ8 与 µ16 在 0.30–0.40 的每个阈值上都在窗口内穿越，于是可以直接读穿越点，得到**不含拟合**的比值：

| τ | 直接穿越法（三 seed 均值） | 逐种子 |
|---|---|---|
| 0.30 | 1.11 | 1.00 / 1.00 / 1.33 |
| 0.35 | 1.17 | 1.25 / 1.00 / 1.25 |
| 0.40 | 1.13 | 1.00 / 1.20 / 1.20 |

斜率比给出 **1.23**，与直接法均值 1.14 相差 **+8%**；直接法本身的分辨率就是 ±1 个 rollout（1.00 与 1.33 之间跳），这个差距落在分辨率内。

**结论**：在线性假设能被独立检验的那一对上，它没有被推翻。这是把斜率比外推到 µ1（删失端）的唯一凭据，也是 C8 里"方法自检"那一条的全部内容。它**不能**证明 µ1 段也线性——µ1 是加速的（分段斜率 ×1.23），µ8/µ16 是减速的（×0.50 / ×0.51），所以线性假设在两端都偏乐观，方向使真实比值偏区间低端。这条限制写进了 C8 的 note。

### 1.4 删失下界（不依赖任何假设）〔实测〕

µ1 在 0.30 上从头到尾没穿，只能说 `N_τ(µ1) > 32,768`。配合快臂的穿越点得到：

- `N_τ(µ1)/N_τ(µ8) ≥ 2.00`
- `N_τ(µ1)/N_τ(µ16) ≥ 2.67`

这是硬结论，任何读法都得满足。斜率比的 4.98 / 6.14 在它之上，不自相矛盾。

### 1.5 与论文 Eq.(5) 的关系（措辞已固定）

点估计 6.14 与论文的 6.1× 数值接近，**不写成复现**。四条理由：判据不同（斜率比 ≠ 原文 `N_τ`，progress 定义也不同）、任务/模型/题池不同、原文那个数在 `claims.yaml` 里曾把方向写反、窗口区间 [3.59, 9.17] 宽到只能支持"同向、同量级"。

### 1.6 C8 怎么登记的

写进 `analysis/claims.yaml`，同时加 `revisions` 段留痕：

- **新增** C8（status `pending`，evidence = `analysis/out/slope_ratio.json`），并注明它是**事后（post hoc）登记**——看过九个 run 之后才定的判据，产出的数是描述性的，不得写成预注册预测。
- **标注**（不改原文）C3 的比值方向笔误。
- C1–C7 的措辞、阈值、status 一个字没动。`trace.py --strict` 现在 **12 条全 `[ ok ]`**（pending 8 / verified 1 / default 3）。

## 2. R2：per-prompt 日志 + zero_var 改口径

### 2.1 加了什么

| 文件 | 改动 |
|---|---|
| `src/prompt_log.py`（新） | `group_summary()` 出四个组级统计；`build_record()` 一行存一个 rollout 的 prompt id + 4096 位正确性 + 4096 个 reward；`truncate_to_rollout()` 供 resume 用；`unseen_vs_seen()` 算首见 vs 重见 |
| `src/metrics.py` | SCHEMA 新增 4 个 optional 字段：`zero_var_correct_frac`、`group_all_correct_frac`、`group_all_wrong_frac`、`group_icc` |
| `src/train.py` | 每 rollout 写 `prompts.jsonl`（约 50 KiB/rollout，对比 npz 的 25–30 MiB）；resume 时先截断再追加；print 行加 `zvC=` |
| `tests/test_prompt_log.py`（新，12 项） | 全对/全错计数、iid 反事实、ICC 手算对照（含一个刻意算错的陷阱）、退化情形、round-trip、长度校验、截断、首见/重见、schema 向后兼容、prompt_idx 取法 |

**ICC 是这次最重要的新量。** 它回答"名义 4096 个 response 实际买到了多少独立观测"：

```
ICC = (MSB − MSW) / (MSB + (G−1)·MSW)    设计效应 = 1 + (G−1)·ICC
```

`group_icc` 写成 optional 且允许 `null`（全组数值完全无变异时 0/0，返回 `None` 而不是编一个 1.0）。**旧数据零破坏**：`check_schema.py --strict` 对 `runs/mu1_s0`、`mu8_s1`、`mu16_s2` 全部仍 `[OK]`。

顺带修掉一个手写公式 bug：初版把 grand mean 写成 `sum(group_sums)/n_groups`（组的**计数**均值），会让 SSB 大 G² 倍、ICC 完全失真。测试里那个手算 ANOVA 的用例就是为抓这个而写的。

### 2.2 旧指标错在哪（用已归档的 72 个 group 实测）

`analysis/group_grain.py`（新）从 `samples.jsonl` 里取出全部 72 个 group（每 run 8 rollout × 1 group），算：

| arm | groups | pass(这批) | pass(全局) | 全对 | 全错 | reward 口径 zvR | correct 口径 zvC | ICC |
|---|---|---|---|---|---|---|---|---|
| µ1 | 24 | 0.208 | 0.269 | 0 | **9 (37.5%)** | **0.000** | **0.375** | 0.198 |
| µ8 | 24 | 0.401 | 0.459 | 3 (12.5%) | 2 | 0.083 | 0.208 | 0.296 |
| µ16 | 24 | 0.401 | 0.517 | 2 (8.3%) | 3 | 0.083 | 0.208 | 0.258 |

与 iid 反事实对照（用全局 pass 算 `p^8`）：

| arm | 观测全对 | iid 期望 | 倍数 | 观测全错 | iid 期望 | 倍数 |
|---|---|---|---|---|---|---|
| µ1 | 0 | 0.00002 | — | 37.5% | 8.16% | **4.6×** |
| µ8 | 12.5% | 0.20% | **62×** | 8.3% | 0.73% | 11× |
| µ16 | 8.3% | 0.51% | **16×** | 12.5% | 0.30% | 41× |

三条结论：

1. **`zero_var_group_frac` 在 µ1 上把 37.5% 的全错组报成 0.000。** 直接原因是 reward 带格式奖励（−0.1 / 0.05 / 0.1），八条全错的回答只要格式不全一致，这个组就不算"零方差"。所以旧字段在弱策略上量的是"全错**且**格式稳定"，在强策略上量的是"全对"，**不是同一个量**。这坐实了 §8 的机制判断，而且数量级比原来的估计更极端（原来只能从 0.46% vs 8.16% 反推，现在有直接的组级观测）。
2. **组内正确性强正相关。** ICC 0.198 / 0.296 / 0.258，设计效应 `1+7×0.25 ≈ 2.75`。这独立印证了 `slope_ratio.py` 里选 `design_effect = √3` 当保守档不是随手取的。**报 CI 时必须用膨胀后的档**。
3. **µ8 与 µ16 在这 24 个 prompt 上的组级成功数完全相同（3.208/8）**。这是样本量的直接后果：24 组 × 8 = 192 responses，SE ≈ 0.036，两臂 5.8pp 的全局差不被这批 prompt 分辨。记录在此，防止有人拿它当"µ8=µ16"的证据。

ICC 的 95% 区间半宽约 `1.96/√21 ≈ 0.43`——24 个组只够说"ICC 明显大于 0"，不够说它到底 0.2 还是 0.5。文档与报告都按这个口径写。

## 3. R3 / R4 的现状

两个都要租卡，按纪律**未启动**。要点先记在这里，决策卡另出：

- **R3（warm-restart 探针）**：只把 µ1_s0 续 1 个 rollout。严格说这不是"续跑"而是"重启后看一步"——lr 会从 2.48e-6 跳到 3.36e-5（13.6×），所以它测的是"高 lr 一步能推动多少"，**不能**用来外推 r8–r18 的曲线形状。它值的唯一场景是先便宜地确认"续跑不会崩"。
- **R4（续到 19，3 seeds）**：约 7.9 h / ¥16。它的边际价值在 R1 之后已经从"得结论"降级为"检验线性假设"。**但是**，如果 R1 的结果要写进简历或对外材料，R4 是唯一能回答"你这个斜率比是不是被线性假设撑起来的"的实验。另外两条必须一起报的威胁：题池复用从 2.25× 升到 4.9×（后段基本全是复习）、以及 `--num-rollouts 19` 的余弦周期重算带来的 warm restart。
