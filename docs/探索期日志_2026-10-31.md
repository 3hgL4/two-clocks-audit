## 一、本轮产出

### 1. 重抽机制（B/C 臂）
- `src/resample.py`：组判定 + 补满循环。
  - 判定口径：**B（accuracy）**= DAPO 式 acc∈{0,1} 拒收，用 `verify.is_correct` 计数（合成奖励无法还原 acc=0——格式 bonus 使全错组奖励为 -0.1 非零）；**C（variance）**= 组内合成奖励 std（ddof=1）< 1e-8 拒收，**阈值与 `grpo.group_advantages` 置零口径逐位一致**（单测有专项）。
  - 补满规则（冻结文本 §三 字面实现）：从同一置换**后续位**逐轮补抽，每轮抽"还缺的组数"，直到 512 混合组或重抽上限（cap 只计补抽 prompt）；同 seed 全程纯函数。
  - **丢弃组完整归档**：`rollouts/r{idx}_discarded.npz`（被丢弃组是审计对象，其准确率/格式统计是 Phase-0 式证据，不能只记计数）。
- 后端 seed 推导加 `attempt`/`response_offset`：**round1 与 A 臂逐 token 同种子**（B/C 的首轮生成与 A 臂配对），补抽轮偏移 10_000_007 不与首轮流重叠。
- `train.py` 集成：等预算口径入账（meter 记 **attempted** completion tokens，kept/discarded 拆分进 metrics 行）；Br_eff 分区守卫（cap 截断时报错而非静默丢组）；新增 resample 字段落 metrics（row 0 记账制）。
- `data.py` 导出 `rollout_permutation`（与 `prompt_batch` 前缀一致，有单测钉住）。

## 三、held-out 评测入口（tools/eval_heldout.py）

- **训练条件镜像**：raw prompt（无 chat template）、temp 1.0 / top_p 1.0 / max_tokens 512（= 训练采样配置）、判分用 `src/verify.is_correct`（与 GRPO 奖励的 correctness 同一函数）——训练侧 pass 率与评测侧 pass 率是同一统计量在不同 prompt 集上的读数。
- **采样纪律**：沿用战役 seed_per_request 结论（单 seed 下 n>1 样本近乎相同），每 prompt 展开 k 个独立请求，种子 = `seed*1_000_003 + i*k + j`，同 seed 逐位可复现。
- 产出：`items_<pool>.jsonl`（逐 prompt 逐样本判定）+ `summary_<pool>.json`（pass/pass_any/format 率 + by_depth + by_aggregation 分解 + 池 sha256）。支持 `--adapter`（vLLM LoRA，max_lora_rank=64）评 checkpoint。

## 六、三臂小规模对比结果（2026-11-01 00:15 ALL_DONE，GPU ≈¥3/1.5h）

### 评测（heldout_counting_512，n=4，temp 1.0，同一冻结池）

|---|---|---|---|

- 同 seed 配对差：**B−A = +0.25pp**（−0.35/+0.43/+0.68）；**C−A = +0.73pp**（+0.97/+1.02/+0.20，3/3 为正）。
- 基座参照 0.2212 —— **所有臂都还停在基座水平**。单 run 评测抽样 SE≈0.9pp，n=3 下 ≤1pp 的差异不可判读。**本轮的定位是机制验证与量级体检，不是假设检验**：2 周期 × 512 响应远不足以移动 held-out pass（与 SAC-µ 教训一致：该规模下同臂漂移 > 任何处理效应）。

### 机制与记账（本轮的真正产出）

1. **B 臂重抽大规模真实触发**：512 训练响应实际抽了 736-768 条（28-32 组被拒），attempted tokens 223k vs A 臂 143-157k → **等批次下 B 多花 ~45% rollout 算力**。等预算口径已入账（completion_tokens_attempted/discarded 拆分）。B 臂保留批 pass 0.30-0.35 vs A 0.21-0.24 = 过滤的**选择效应**（保留中段准确率组），非学习效应——这正是 Phase 0 预言的形态。
2. **C 臂几乎不触发**（每周期 0-2 组，~0-2%）：与 Phase 0"全错组 99.4% 有方差"一致——合成奖励下全错组因格式 bonus 差异仍有方差；零方差组的真正来源是后期全对组（Phase 0：acc=1 对称占比 0.12%→2.01%）。**C 的窗口在训练后期**，2 周期看不到。
3. 评测入口稳定：10 次评测全部成功，逐 prompt items + sha 溯源齐全；格式率各臂 0.79-0.81，无格式退化。

### 对确认期设计的含义（探索期结论，待小规模验证后冻结）

- 效应量现实检查：若 B/C 的真实效应 < 1pp，正式实验需要能分辨 ~1pp 的功效（3 seed 配对 + prompt 聚类 bootstrap 可能仍不够，或需更多周期把效应做大）。
- 等预算对比的**计费单位必须是 attempted tokens**：B 天然多抽 45%，按 batch 数对比会系统性偏向 B。
- C 臂假设应改写为**训练后期**假设（全对组占比上升 → 方差过滤触发率上升 → 末段差异），2 周期设计对 C 无分辨力，正式 C 臂至少要跑到 acc=1 对称占比显著抬升的阶段。

## 九、mod 族判读预注册（2026-11-01 18:35，mod B 臂出结果前写下）

> 本节在 fsa_mod_b_s0-2 评测数字可见之前成文，用于约束事后解读。

**已知事实**（判读前）：计数族 B−A = +0.30/+1.81/+1.17pp（均值 +1.09，3/3 正）；B 的剂量代价 = attempted tokens +31~37%（1.69-1.77M vs A ~1.29M）；mod A 臂三 seed 0.1233/0.1206/待查；would-be 分析 mod 剂量应 ~2x 计数族。

**设计缺口声明**：三臂为等保留批（4096 kept）设计，B 臂为凑满多抽 → **本设计无法区分"过滤提升样本效率"与"B 变相多算 35% SGD"**。无算力对齐 A 臂（A×~11 周期）。

**判读规则**（预承诺）：
1. mod B−A 为正且三 seed 一致 → 记"方向性信号"，**禁写"B 有效"**；claim 上限为"过滤组在两任务族一致高于基线组，但等保留批设计下含 ~35% 算力混杂，归因需算力对齐对照"。
2. mod B−A 与计数族方向不一致或均值 |Δ|<0.5pp → 结论"此规模下效应 <1pp，与 29-50% 算力代价不成比例"，按成本收益负结果收口，不加 run。
3. mod B−A 显著为负（三 seed 一致、<−1pp）→ 新现象：高剂量过滤在低基座任务上可能伤害学习（淘汰多样性？），单独记录，不并入 1/2。

**若走规则 1 的后续决策点**（留给用户）：算力对齐对照 A×11 周期 ≈ ¥7/seed（1 seed 先行可至 ¥7，3 seed 全上 ¥21）。该 run 是"DAPO 过滤是否真提升样本效率"的唯一裁决者。
