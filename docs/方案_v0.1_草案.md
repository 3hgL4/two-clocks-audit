- 一句话（v0.8）：**DAPO 完整系统已在规则奖励上叠加 soft overlong punishment——组内响应长度触发不同惩罚时，acc∈{0,1} 组可能出现非零 reward 方差而被 accuracy 规则过滤，即该间隙在其自身系统内已存在。本项是对这一既有过滤规则的审计与实验评估：在去除长度惩罚的受控 harness 中隔离格式 bonus（正确性奖励恒定的组内，它是组内奖励差异的唯一来源），评估奖励差异与过滤策略的训练后果（RCT）。**

## 一、研究问题

**R1（离线，已完成）**：acc∈{0,1} 组的组内奖励方差与归一化 Advantage 绝对值占比是多少？DAPO 式 correctness 过滤会丢弃哪些仍有非零组内差异的组？（描述性统计；acc0/acc1 对称报告）

**R2（RCT，已立项待冻结稿 v1.0）**：等预算下三种策略的对照——**臂 A** 不过滤（拟复用 runs/mu16_s0-2，须过六项核验）、**臂 B** accuracy 过滤（丢弃 acc∈{0,1} 组并重抽补满）、**臂 C** 方差过滤（拒绝零方差组并重抽补满）；以冻结集 pass@1 为主指标，格式有效率轨迹等为机制诊断。设计细节见 §三/§十五。

**指标命名与口径（v0.4 钉死）**：表中"归一化 Advantage 绝对值占比"= 该类组 Σ\|A_i\| / 全批 Σ\|A_i\|。**聚合层级已钉死为响应级等权**：A 为组内归一化 advantage（grpo.py 口径 (r−μ)/(σ+1e-4)、ddof=1、零方差置 0），每条响应权重 1、与长度无关；分母 = 全批 512 组 × G=8 = 4096 条响应的 \|A\| 总和。**注意实际损失是 token 加权的**（grpo.py `grpo_loss` 默认 `norm="token_mean"`，全部有效 token 池化平均），故响应级占比 ≠ 实际梯度权重。已补算 token 加权敏感性口径（每条响应按 completion token 数加权）：

| 周期 | acc=0 响应级 | acc=0 token 加权 | 被丢弃组 响应级 | 被丢弃组 token 加权 |
|---|---|---|---|---|
| r0 | 31.7% | **35.3%** | 31.8% | 35.3% |
| r4 | 11.6% | 15.8% | 13.2% | 16.9% |
| r7 | 7.5% | 10.8% | 9.5% | 12.2% |

错答响应更长 → token 加权后份额系统性更高。两个口径都是**描述性统计**：不反映梯度方向是否有助于任务成功率，不得写成"advantage 质量 / 梯度质量 / 被过滤的性能贡献"。报告时两口径并列，写明各自分母。

**掩码与统计阶段（v0.5 钉死）**：token 加权口径的"有效 token" = **全部 completion token**——npz 的 `completion_flat` 为打包存储，长度 == Σ`completion_len`（已核，r000 为 1,183,331 tokens），**无 padding、不含 prompt token、无掩码剔除**（最短响应 1 token 也全额计入）。统计阶段：每个 run-周期（512 组 × 8 响应）独立算一次份额，表中数字 = 3 个 run（mu16_s0/1/2）的**等权均值**；r0/r4/r7 为单周期截面，非末段窗口。

三条核心读数（mu8/mu1 同构，剂量-响应一致）：

1. **训练早期，acc=0 组占归一化 Advantage 绝对值的约 1/3**，且其中 99.4% 有非零组内奖励方差。DAPO 式 accuracy 过滤在 r0 会把这部分组整体丢弃。
2. **全错响应的格式有效率从 72.5% 升到 94.9%**（mu16，8 周期；mu1 同期只到 79.1%——更新数越多升得越高，剂量-响应一致）。这是训练轨迹中的描述性变化，非因果。
3. **对称证据（v0.3 补入）**：acc=1 组同样可有组内方差（本 harness 的格式 bonus：reward 0.9/1.05/1.1），归一化 Advantage 绝对值占比 0.12%（r0）→ 1.59%（r4）→ 2.01%（r7，3 seed 均值）。即 accuracy 过滤丢掉的"非零差异组"在两侧都存在；注意 DAPO 完整系统里 acc=1 侧的偏离来源是 overlong 惩罚、本 harness 无长度惩罚，来源不同须分开表述。
4. 随训练推进效应衰减（acc=0 占比 31.7%→7.5%）：若过滤有害，伤害应集中在前半程。此为可检验预测，由 RCT 判定。

**边界**：以上是行为-梯度分解，不是因果；"格式学习是否instrumental 于正确率学习"只能靠 R2 回答；µ 阶梯臂（sac/sacS/sacR）npz 不在本地，未覆盖。

## 三、R2 设计（已立项；**暂定设计**，探索期可改；确认阶段启动时誊入 HYPOTHESIS.md）

- **臂 A（现状）**：拟**复用 runs/mu16_s0-2**（配置与 SAC-µ 基线一致：µ16、G=8、8 周期、pool sha d781f955）。**复用核验清单（六项，逐项写入判据冻结稿，缺一不可）**：①代码版本（commit 与分支）；②训练配置（config.resolved.yaml 与冻结稿逐项一致）；③数据顺序（pool sha 与置换序列）；④seed；⑤预算口径（与主口径一致的计量）；⑥评测协议（冻结集、判分、末段窗口）。**任一项不符 → 该 run 降级为"历史参考"，不进配对 RCT**，A 臂改跑 3 新 run（预算 +¥12–15，重估）。
- **臂 B（DAPO 式过滤）**：每周期生成后丢弃 acc∈{0,1} 组，从同一置换的后续位重抽新 prompt 补满有效组数，直到 512 个混合组或重抽上限；与 A 臂**同一总生成 token 预算与停止规则**（见下，含被丢弃响应的生成 token）。
- **等预算口径（v1.0 冻结文本，2026-10-31 定案）**：主预算 = 每臂**固定的总 rollout 生成 token 预算**；**所有生成响应均计入，包括被过滤、丢弃和重抽产生的响应**。**主计数 = 所有尝试的 completion token**（生成成本口径）；prompt token 单独报告（避免不同任务曝光的 prefill 成本差异漏出主预算），两分量墙钟为次要口径。各臂使用相同任务池、预先固定的采样顺序与生成上限；**停止规则 = 预注册的组边界停止**（预算检查在周期边界执行，周期内不中断；实际超额如实报告，须 < 单周期生成量，各臂同规则）。更新数、有效任务曝光数、重抽量作为结果报告，不强行配平；等更新数仅作单独的敏感性分析。
- **第二任务族（v1.0 定案：可程序验证的整数模运算）**：事实核验——现有池 prompts_mixed2000 为**程序生成**的整数链任务（区间+变换链+聚合；2000 条中模运算 0 条；答案全为整数；解析器提取 `Answer: <int>`）。定案：**扩展现有生成器新增模运算算子/聚合**（如 mod 类变换或 sum_mod 聚合），固定 seed 生成独立 pool，**训练池/冻结测试集/解析器/生成规则全部 sha 冻结后纳入**；沿用相同单整数答案格式与格式奖励，**不引入新判分器**。作为**独立外部复验族，单独报告**，不与计数任务合并主 Pass@1。若生成器冻结未完成 → 结论限定于合成计数任务，不为凑第二族临时拼数据。
- **判据草案**：P1＝末 2 周期（r6–r7）冻结集 pass@1，**主对比 = B−A**（C−A、B−C 为次要对比，报告但不作主结论），**同 seed 相减**得 3 个配对差，逐 seed 列结果 + 配对差 bootstrap 95% CI；**CI 重采样按 prompt 聚类**（继承 SAC-µ 冻结稿 P1 口径、参照 `c4_control_report.py`：两臂共享同一批冻结测试任务，逐任务观测不是独立样本，聚类单元 = prompt，独立单元 = seed，n=3 → 定位"初步证据"，不宣称稳健/显著）；P2＝全错响应格式有效率轨迹（描述性，见下）；P3＝成本两分量口径（rollout+update，old_logp 计入 update）。
- **格式有效率口径钉死（v0.4）**：mu16 3 个 run；每 run-周期内分母 = 该周期全错响应数（全批 4096 条响应中 correct=False 者，数量随周期变化）、分子 = 其中 bonus>0 者；**先按 run-周期算比例，再对 3 个 run 等权求均值**。非池化、非按 token。72.5%（r0）→94.9%（r7）为训练轨迹描述性变化，与过滤策略无关（RCT 前无任何过滤臂）。
- **预算估计（v1.1 簿记统一）**：**6 新增 + 3 复用 = 9 总臂运行**（B/C ×3 seed 新增，A 复用 runs/mu16_s0-2），µ16 单 run ≈¥4 + 重抽开销 ≈15–25%，**≈¥24–30**（以执行卡实测为准）；A 臂六项核验不过则 A 改跑 3 新 run（+¥12–15，重估）。原"3 run ≈¥15–30"为仅 B 臂的旧估算，作废。
- **风险**：① A 臂复用的口径核对不过则需重跑 A（+¥15）；② 结果方向不定——若 B≈A，结论是"被 accuracy 过滤保留/丢弃的组内差异与正确率学习可分离"（同样可写）；③ 计数任务/1.7B 规模的外推边界须写进报告；④ 重抽实现的确定性（同 seed 可复算）须有测试。
- **定义钉牢清单（v0.3，全部进判据冻结稿）**：
  - `accuracy filter`（B 臂）：accuracy = 组内 `is_equivalent` 计数比例；全对 = acc==1、全错 = acc==0，逐组判定，无阈值灰区。
- **臂 C（方差过滤 + 重抽，v1.0 修正实现定义）**：**拒绝组内 reward 方差为零的组，并从同一置换后续位重抽补满有效组数**——不是仅屏蔽。理由：GRPO 本身已把零方差组 advantage 置零，若 C 只屏蔽不重抽，其梯度更新与 A 臂实质相同，不构成独立臂（v1.0 前对齐指正）。修正后的对比含义：**B vs C = 过滤判据（accuracy vs reward 方差）在同一重抽机制下的对比**；**A vs C = 是否对零方差组补采样的对比**。判定依据 = Advantage 计算所用的原始组奖励（correctness + format bonus 合成值，与 advantage 同源同阶段），阈值 = 组内 reward 标准差（ddof=1）< 1e-8（与 grpo.py `group_advantages` 置零口径逐位一致）；**本 harness 无长度惩罚**。
  - `no filter`（A 臂）：现状；与 B/C 臂对齐 = 相同 pool 置换、相同每周期起点、相同有效组数目标 512；更新数对齐方式随主预算口径确定（见下）。
  - **主估计对象**：主口径 = 等总 rollout token（含被丢弃响应），各臂训练至相同预算停止；更新数与任务曝光数为结果指标；等更新数口径为次要敏感性。因果结论唯一来源 = 冻结集 Pass@1；梯度范数份额为在线诊断量，不单独证明梯度方向有益。

## 六、v0.2 更正记录（2026-10-31 晚，外部 review 复验 DAPO 原文后）

以下更正经对 arXiv:2503.14476v2 原文独立复验后采纳，覆盖上文冲突表述：

1. **命题重述**：DAPO 的过滤规则是 **accuracy-based**（Eq.11 约束用 `is_equivalent`，过滤 accuracy∈{0,1} 的组），其"组内同奖励→零优势"论证仅在二值奖励下成立。关键事实：**DAPO 完整系统奖励已非二值**（规则奖励 ±1 + Soft Overlong Punishment 长度惩罚，"This penalty is added to the original rule-based correctness reward"），故其自身系统内 acc=0 组即可有非零 reward 方差而被 accuracy 规则过滤。研究问题改为：**accuracy-based 过滤规则与 reward-方差零优势机制在复合奖励下的不一致，实测其代价**。不再使用"证明全错组不是零信号组"的表述（方差 ≠ 有用任务信号，后者由 RCT 判定）。
2. **消融表述**：Table 1 为渐进累计叠加（"progressive"，30→36→38→41→42→50），Dynamic Sampling 无独立消融；引用一律写"渐进消融序列中增量最大的一项（42→50）"，禁写"消融最大单项"。
3. **信号指标须冻结定义**：离线指标 = Σ|adv| 份额（组内 Σ|adv| / 全批 Σ|adv|，adv 为 grpo.py 口径 (r−μ)/(σ+1e-4)、零方差置 0），**描述性量，不得写成策略梯度范数份额**；RCT 在线指标 = 被过滤组的实际梯度范数份额（训练时记录）。两者进判据冻结稿。
4. **三臂定案**（review 建议，与加强档一致）：A 不过滤（现状）；B DAPO accuracy-based filtering + 重抽；C 仅过滤 reward 方差为零的组（保留"全错但格式不同"组）。C 臂用于把"方差存在"与"信号有用"解耦。
5. **预算口径**：主口径 = 总 rollout token 数；墙钟为次要口径；记录各臂任务曝光数（prompt 分布因过滤改变）。
6. **证据档位**：3 seed → 报告定位"初步证据"，冻结集小差异不写"稳健提升"；加强档若加 seed/周期按冻结稿执行。
7. 测试集不参与过滤规则设计、调参与筛选（与既有纪律一致，显式入冻结稿）。
