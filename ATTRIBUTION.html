1. 为什么要做这三组归因

主审计给出两条互相矛盾的事实：

  1. 同一预算下 pass 排序 µ16 0.484 > µ8 0.435 > µ1 0.262（3/3 seed 同向）；
  2. 但 µ 在固定 Br 时与 b 完全共线（b = Br/µ），所以"µ 大更好"至少有三种互斥解释： - µ 本身（同一批数据被切成更多次更新 → 每步的 off-policy 程度不同）； - b（每步用的样本更少 → 梯度噪声更大，可能恰好有利或不利）； - σ 的估计口径（micro_group_responses=8 固定，不随 b 缩放）。

三种解释指向完全不同的工程处方：若主因是 µ，处方是"同一批数据多切几次更新"；若主因是 b，处方是"每步少取样本、多走几步"，两者在实现上不是一回事。所以必须拆。

三组实验各自负责一刀：

实验 切什么 代价 结论方向
C10 b×µ 2×2 µ 与 b 的共线 6 run / ¥27.33 正向：µ 是主因
C11 dual-clip 消融 clip 上界是不是承重墙 3 run / ¥11.06 惰性：clamp 从不触发
C9 离线 σ 分解 σ 的 µ 依赖来自切分还是陈旧 ¥0（不训练） 否定：两个都不是

2. 三个实验的设计，以及为什么只能这么设计

2.1 C10：b×µ 2×2 为什么不是干净的 2×2

Br = b · µ 是恒等式。固定 Br=4096、让 µ ∈ {8,16}、b ∈ {256,512}，四个组合里只有两个存在（µ8@b512 与 µ16@b256）；另外两格必然改变 Br：

格 µ b Br 相对标准格
mu8_b512 8 512 4096 1.00×（标准）
mu16_b256 16 256 4096 1.00×（标准）
mu8_b256 8 256 2048 0.50×（偏保守）
mu16_b512 16 512 8192 2.00×（偏乐观）

两个偏差方向相反：第 3 格数据少一半，会低估它自己的 pass；第 4 格数据多一倍，会高估。若"b 是主因"，这两个偏差分别把 b 效应往下、往上拉——净效果不确定，这一点必须在读结果前说清。

另有一层：prompts_per_rollout 在两格里不同（256 vs 1024），所以四格的 pass 是在不同 prompt 子集上估的。这不是可修的瑕疵，是"想改 b 就得改每 rollout 的 prompt 数"的直接后果。

2.2 C11：唯一单变量

clip_delta 上界从 10.0 改成 null，其余一个字节不动。这是三项归因里唯一没有混淆的实验，也就是它给出的结论最硬——而它给出的结论是没有效应。

2.3 C9：原始设计在数学上就不可能成立

这条要单独记，因为它是本项目唯一一次"写脚本时才发现判据本身错了"。

原始设计是：离线用不同的 b 切分同一份数据，算 σ，若离线 σ 曲线与训练中的 σ 曲线一致，则 σ 的 µ 依赖得到归因。这个设计不成立：σ 是组内梯度范数的变异系数，而组大小固定为 8（micro_group_responses）；改 b 只改变"有多少个组"，不改变"每组多大"。变异系数的期望与组数无关，所以离线 σ 在 b 变化下必然平坦，不可能"复现"训练中的增长。

改成可做的形式：固定一份归档数据 D（mu1_s0/r000，4096 条 responses，由初始策略产生），在三个 adapter（r000 / r003 / r007，累积 off-policy 陈旧度递增）× 三种切分（µ'=1/8/16，即每片 4096/512/256 条）下各算一次 σ，得 3×3 表。两个假设：

  • H1（切分无关）：同一 adapter 下三种切分的 σ 相对极差 < 5%；
  • H2（陈旧相关）：σ(a7)/σ(a0) ≥ 1.20。

3. 结果：能说什么 / 不能说什么

3.1 C8：斜率比代理（描述性，不是 C3 的替代品）

方法。 若 pass 对 responses 在窗口内近似线性，则 N_τ(µ)/N_τ(µ') = slope(µ')/slope(µ)，τ 自动消掉。这是它相对"续跑穿越"的主要优势：τ 取 0.30 还是 0.35 不再是一个会跑空预算的参数。

主窗 r0–r7（三臂共享），逐 seed 比值后再取均值：

比值 点估计 逐 seed 离散
N_τ(µ1)/N_τ(µ8) 4.98 4.66 / 4.80 / 5.47 极差 0.81
N_τ(µ1)/N_τ(µ16) 6.14 5.99 / 5.62 / 6.80 极差 1.18
N_τ(µ8)/N_τ(µ16) 1.23 1.28 / 1.17 / 1.24 极差 0.11

方法自检（这是这条判据最该看的一段）。 唯一能被独立检验的一对是 µ8 vs µ16：两者都能在窗口内穿越某些阈值，因此可以把"直接读穿越点"（不依赖线性假设）与"斜率比"（依赖线性假设）对照。直接读穿越点得 1.11 / 1.17 / 1.13（均值 1.14），斜率比给 1.23，差 +8%，落在 ±1 rollout 的网格分辨率之内。结论：线性假设在唯一可检验的那一对上没有被打翻，但也没有被证实——这只是一个不自相矛盾的检查。

窗口敏感性：系统误差比统计误差大一个数量级。

窗口 µ1/µ8 µ1/µ16
r0–r4（5 点） 7.31 9.17
r1–r7 4.77 5.87
r2–r7 4.11 5.10
r0–r7（主窗） 4.98 6.14
r4–r7（4 点） 2.82 3.59

窗口区间 [3.59, 9.17] 是 −41% / +49%，而三元统计 CI 的宽度只有约 ±10%。两套误差必须同时报，只报一套就是选择性呈现。

能说：在这批数据、这个窗口、这个线性假设下，达到同一 pass 水平所需 responses 的比值约为 4.98（vs µ8）与 6.14（vs µ16），且三个 seed 方向一致。 不能说：这是 C3 的 N_τ（判据不同）；不能说这是复现论文的 6.1×（任务、模型、题池全不同，且本判据本身是事后登记）；不能说 τ=0.30 时也成立（τ 无关是线性假设的推论，不是测量结果）。

3.2 C10：µ 是主因，b 不是（本报告主结论，已升格）

响应取 r7 端点 pass（.git-ignored 的 analysis/out/bmu_2x2.json 可重算）：

格 µ b responses/rollout r7 pass（s0 / s1 / s2） 均值 单 run 成本
mu8_b512 8 512 4,096 0.4453 / 0.4805 / 0.4521 0.4593 ¥3.59
mu16_b256 16 256 4,096 0.5071 / 0.5283 / 0.5149 0.5168 ¥3.55
mu8_b256 8 256 2,048 0.4189 / 0.4316 / 0.4644 0.4383 ¥1.88
mu16_b512 16 512 8,192 0.5670 / 0.5780 / 0.5562 0.5671 ¥7.23

主效应（n=3，t(0.975, df=2)=4.303）：

效应 均值 95% CI sd
µ 主效应（8→16） +9.31 pp [+5.77, +12.85] 1.43
b 主效应（256→512） +3.56 pp [−1.04, +8.17] 1.85
交互 +2.93 pp [−3.67, +9.53] 2.66
  • µ 主效应 CI 不含 0；b 主效应 CI 含 0；交互 CI 含 0，故两效应在本数据上可加。
  • 逐 seed 配对差（µ 效应 − b 效应）：+6.18 / +4.79 / +6.27，均值 +5.75 pp [+3.68, +7.82]，3/3 同号。

为什么两个主效应可以直接比。 这是本条最关键的一步论证：两个效应各自都是在"固定另一个因子"下把预算翻倍——b=256 列比较 2048→4096，b=512 列比较 4096→8192；mu=8 列比较 2048→4096，mu=16 列比较 4096→8192。所以两句话是同一句：

同样把预算翻一倍，拿去多切几次更新的收益是 +9.31 pp，拿去每轮多采数据的收益是 +3.56 pp。

能说： - 在本数据上，µ 是主因：同一 b 下 µ 翻倍的收益约为 b 翻倍的 2.6 倍（配对差 +5.75 pp，CI 不含 0）； - 两效应可加：没有证据表明"µ16 的劣势能靠加大 b 补回来"（交互 CI 含 0，这一支判据不成立）。 不能说： - 不能说"b 完全无效"——CI 含 0 只说明"在这 3 个 seed、这个量级上测不出来"，不等于零； - 不能说"µ16 的劣势能用 b 补偿"——交互不显著就是不可判定，不是"差不多能补"； - 不能说这是严格的 2×2——两新格的预算分别是 0.5× 与 2×，且 prompt 子集不同（§2.1）。

α 校正未做，必须写在这里： 上述 CI 都是 α=0.05 口径。本项目有 2 条主结论（C3 预注册 + C10 事后升格），严格应校正到 0.025（t 分位 4.303 → 6.205）。按 6.205 重算区间会变宽、下界下移；以逐 seed 配对差 6/6 同号、均值 +5.75 pp 的量级看，下界大概率仍为正——但"大概率"是外推，本项目没有做这一步计算。简历与口头陈述里不要省略这一条。

3.3 C9：σ 的 µ 依赖既不是切分也不是陈旧 —— 本项目没有解释它

3×3 表（σ，组内梯度范数的变异系数）：

adapter 累积 off-policy 步 σ(µ'=1) σ(µ'=8) σ(µ'=16) 组内相对极差
init — 0.070378 0.070289 0.070189 0.27%
r000 0 0.068831 0.068744 0.068645 0.27%
r003 3 0.069368 0.069294 0.069191 0.26%
r007 7 0.070199 0.070128 0.070013 0.26%
  • H1（切分无关）成立：极差 0.26–0.27%，判据要求 < 5%，余量约 20 倍。
  • H2（陈旧相关 ≥ 1.20）不成立：σ(a7)/σ(a0) = 1.0199 / 1.0201 / 1.0199（三个 µ' 一致），相差一个数量级。

按 C9 自己写的判定规则，这落到第三支："σ 的 µ 依赖既非切分也非策略陈旧，必须列为未解释的混淆项"。

为什么这条重要：σ 是 d 的分母，而 d0 随 µ 上升 2.63×（REPORT.md §5.3）主要就是靠 σ 不动、‖ḡ‖ 涨 2.69× 实现的。也就是说，主报告里那个最反直觉的观测（d 随 µ 上升）所依赖的那个量，本项目查不出它为什么不动。

能说：切分本身不重要（20 倍余量）；策略陈旧度在 7 步内不足以把 σ 推过阈值。 不能说：不能说"σ 与 µ 无关"——恰恰相反，训练中的 σ 在 r7 时三臂分别是 0.0663 / 0.0830 / 0.0958（极差 44%），µ 依赖是存在的，只是不来自这两个候选机制。 不能说：不能说"所以 σ 不重要"。它是一个未解释的混淆项，不是一个被排除的项。

补充一个零成本佐证：mu1 与 mu8 的 r0 rollout_data_sha 完全相同（82bbd063…），而 r0 三臂 σ = 0.0663 / 0.0695 / 0.0700（极差 5%）——µ 依赖在起点几乎不存在，只在训练之后长出来。这排除了"初始权重不同"这一解释，但离"为什么长出来"还差一步。

4. 长视界：C12 与一个口径陷阱

µ1 从 8 续跑到 19 rollout（3 seed），用网格口径判定——只在每个 rollout 结束处检查 pass ≥ 0.30，不做 rollout 间插值（插值等于把线性假设当已知，对 C8 是循环论证）。

3/3 命中：

seed 首达 rollout pass 累计 responses 累计成本
s0 r12 0.3130 53,248 ¥6.14
s1 r10 0.3057 45,056 ¥5.06
s2 r10 0.3193 45,056 ¥5.13

命中点逐 seed 不同：s0 在 r11 只有 0.2937，还没过线。不要概括成"µ1 在 r11 命中"。

真正值得记的不是命中，是同一份数据在两套口径下差 1.7 倍。

口径 µ1/µ8 µ1/µ16 相对 C8
C8 斜率比（主窗 r0–r7 线性） 4.98 6.14 —
R4-A 网格（只查 rollout 边界） 3.58 3.89 −28% / −37%

根因是分辨率不对称：µ1 有 19 个检查点，µ8/µ16 只有 8 个（只在 rollout 边界有 pass）。网格化对快臂的膨胀更严重——µ8 的 pass 从 0.2987（连续）到 0.300 需要等一整格，把穿越点推到 idx3，膨胀约 2.0×；µ1 只膨胀 1.04×。

所以：网格数不能当作 C8 的修正值，两者测的不是同一个量。网格口径的价值在别处——它给出一个不依赖线性假设的下界：若把 µ1 再续跑到 19 仍未命中，µ1/µ16 ≥ 6.33。这次 3/3 命中，这个下界支没用上。

6. 不可消除的局限

前四条是设计与预算的函数，补不了；后四条是测量范围的边界。

  1. Br = b·µ 是恒等式 → 真 2×2 不可能固定预算。两新格被迫是 0.5× 与 2×，且 prompts_per_rollout 不同（256 vs 1024），pass 在不同 prompt 子集上估。
  2. µ 同时改三样东西：更新次数、每步样本数 b、以及每步的 off-policy 程度。C10 只把 µ 与 b 拆开，第三项（off-policy 程度）仍与 µ 绑在一起，而 C9 恰恰在这个方向上给出否定结论。
  3. 3 个 seed → t 区间只有 2 个自由度。所有 CI 都宽，且 C10 的效应量虽 6.5 倍于组内离散，仍只是一次小样本估计。
  4. α 未做 Bonferroni（2 条主结论，见 §3.2 末尾）。
  5. 单模型 1.7B-Base + LoRA r=64（可训 3.89%）：绝对标度不可外推，σ 与 ‖ḡ‖ 的量级都受 LoRA 子空间限制。
  6. 单任务 counting、响应 285–300 token、生成上限 512：轨迹短意味着 off-policy 代价可能被低估；C11 的"clamp 从不触发"尤其只在这个长度域成立。
  7. 组粒度只能抽样估：samples.jsonl 每 rollout 只留第一组，故每臂 24 组（全局 72 组），不是全部 512 组。据此得到的全错组比例（µ1 37.5%）与 ICC（0.198/0.296/0.258）只足以推翻旧字段给的 0.000，不足以支撑逐臂排序（REPORT.md §5.10.1）。
  8. µ1 的 19 rollout 不是一条连续曲线：续跑会把 lr 在 r8 从 2.48e-6 拉到 3.36e-5（13.6×），是两个调度段的拼接。C12 只用"是否穿越"这一与调度形状无关的事实，任何依赖曲线形状的推断都不能用它。
